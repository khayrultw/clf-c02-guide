# Domain 2: Security and Compliance (30% of scored content)

Start by asking who owns the control. Then distinguish giving access, gathering evidence, detecting a problem, and preventing it. The task lessons are required; configuration procedures and detailed pricing are outside the expected depth.

## 2.1 — Understand the AWS shared responsibility model

- **AWS: security of the cloud.** AWS protects physical facilities, hardware, networking infrastructure, virtualization, and the components it operates for a managed service. You inherit physical and environmental controls; you do not secure an AWS data-center door yourself.
- **Customer: security in the cloud.** You classify and protect data, authorize identities, configure exposed endpoints and network rules where applicable, secure your code and applications, and choose appropriate encryption, retention, and other service settings. An audit of AWS is not an audit of your workload.
- **Shared controls apply at different layers.** For patching, AWS patches what it operates; you patch what you operate. For configuration management, AWS configures its infrastructure; you configure your guest OS, applications, and service settings as applicable. AWS trains its staff on its controls; you train yours on your controls. This is not two parties performing the same patch on the same machine.

| Service | AWS manages | Customer still manages |
|---|---|---|
| Amazon EC2 | Facilities, physical hosts, and virtualization | Guest OS patching, installed applications and libraries, data, access permissions, and security group settings. If you install your own database here, you also maintain the database software. |
| Amazon RDS | Underlying OS and infrastructure; managed DB engine maintenance | Data, database users and grants, network access, and applicable maintenance, upgrade, backup, and encryption choices. AWS performing maintenance does not remove the need to test upgrades or plan around downtime. |
| AWS Lambda | Servers and execution environment; AWS-managed runtimes receive automatic runtime updates by default | Function code, dependencies, execution-role permissions, data, runtime selection, and rebuilding/redeploying updated container images for container-based functions. |
| Amazon S3 | Storage infrastructure and the service platform | Data classification, bucket and object access, retention and applicable encryption choices. No guest OS to patch; a poorly chosen bucket policy is still the customer's problem. |

**Scenario:** Moving a self-managed database from EC2 to RDS shifts OS maintenance to AWS; it does not shift the authority to decide who can read customer records. Sources: [AWS shared responsibility model](https://aws.amazon.com/compliance/shared-responsibility-model/), [RDS maintenance](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_UpgradeDBInstance.Maintenance.html), and [Lambda runtime updates](https://docs.aws.amazon.com/lambda/latest/dg/runtimes-update.html).

## 2.2 — Understand AWS Cloud security, governance, and compliance concepts

**Security** protects systems and data. **Governance** sets rules and ownership for using cloud (for example, an approved Region or mandatory encryption policy). **Compliance** means meeting applicable laws, contractual obligations, or standards and being able to show evidence. A healthcare provider evaluating US HIPAA obligations, a merchant handling cardholder data under PCI DSS, and an organization subject to a data-residency rule can have different requirements. Check the specific program, service, features, Region, and required agreements rather than assuming a service available in a Region is suitable for every workload. The [AWS Services in Scope by Compliance Program](https://aws.amazon.com/compliance/services-in-scope/) matrix is different from the exam's in-scope list.

[AWS Artifact](https://aws.amazon.com/artifact/) provides AWS audit reports and certain agreements. Use a report to identify controls AWS covers and its scope, or use agreements to review and, where supported, accept applicable terms. Use your own evidence to demonstrate your part. An Artifact download, or a passing configuration check, does not certify your application.

| Data protection need | What to choose | Recognition clue and boundary |
|---|---|---|
| Encryption **in transit** | Use TLS, such as HTTPS, for protected network communication. | Protect a customer sending a payment request. [AWS Certificate Manager (ACM)](https://aws.amazon.com/certificate-manager/) provisions and manages TLS certificates; use with compatible endpoints. A certificate does not encrypt a backup. |
| Encryption **at rest** | Encrypt stored data such as disks, objects, and backups. Depending on the service, use service-managed keys or integrate with [AWS Key Management Service (AWS KMS)](https://docs.aws.amazon.com/kms/latest/developerguide/overview.html). | Protect the stored copy of a report. Check service defaults and choose appropriate key access and policy. An authorized application can still see the data after decryption. |
| Dedicated key hardware and more control | [AWS CloudHSM](https://docs.aws.amazon.com/cloudhsm/latest/userguide/introduction.html) provides dedicated hardware security modules for workloads that need direct control of keys and cryptographic operations. | Consider it for a requirement for dedicated HSMs and customer-managed users and keys. Prefer the simpler managed KMS integration when it meets requirements. |

To find security evidence, start from the question, not from the word “log”:

| Question | Service and where to look | Limits |
|---|---|---|
| **Who changed** an AWS resource, and when? | [AWS CloudTrail](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/view-cloudtrail-events.html) records supported AWS account activity. Start in CloudTrail Event history for recent management events in the relevant Region; configure a trail to deliver logs to Amazon S3 for longer retention and select data events where needed. | Event history is the last 90 days of management events per Region, not every object read or application message. Additional logging can incur charges. |
| **What is happening now?** | [Amazon CloudWatch](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/WhatIsCloudWatch.html) monitors metrics and supports alarms; look in CloudWatch Logs log groups for application, operating system, or service logs collected there. For example, alert on a spike in application errors. | Enable collection/integration where needed and plan access, retention, and costs. A metric alarm is not an inventory of API actors. |
| **How was it configured, and did it meet the rule?** | [AWS Config](https://docs.aws.amazon.com/config/latest/developerguide/WhatIsConfig.html) records configurations of supported resources when configured, shows changes over time, and evaluates selected rules. For example, find when a recorded storage configuration stopped meeting policy. | Configure what to record and evaluate. A rule result is evidence about a setting; use AWS CloudTrail to identify who changed it. |
| **Which identities have or use access?** | In [AWS Identity and Access Management (IAM)](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html), use a [credential report](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_getting-report.html) for IAM user credential status and use [last accessed information](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_access-advisor.html) to guide permissions reviews. IAM Access Analyzer helps identify unintended external access. | A credential report is a snapshot, and last accessed information is a review aid, not a replacement for event logs or justification to remove a rarely used emergency permission without review. |

### Governance at scale

| Service | When to choose it |
|---|---|
| [AWS Organizations](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_introduction.html) | Group accounts for central management. A [service control policy (SCP)](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html) can limit the maximum permissions in member accounts; an SCP does not grant access. See [Task 4.2](04-domain-4-billing-pricing-support.md#task-4-2) for consolidated billing. |
| [AWS Control Tower](https://docs.aws.amazon.com/controltower/latest/userguide/what-is-control-tower.html) | Set up and govern a multi-account landing zone (a standard starting environment) with controls and repeatable account provisioning. It uses AWS Organizations; use Organizations alone when you need account grouping and policies without that opinionated setup. |
| [AWS Service Catalog](https://docs.aws.amazon.com/servicecatalog/latest/adminguide/introduction.html) | Let teams deploy approved products, such as a standard application stack, from a controlled internal catalog. Use a catalog to constrain what people can provision, not to look up who changed an existing resource. |
| [Service Quotas](https://docs.aws.amazon.com/servicequotas/latest/userguide/intro.html) | Check account or regional limits for supported services and request increases for adjustable quotas. For example, check a capacity limit before a large rollout. Quotas are service limits, not permission or spending controls; not every quota can be increased. |

**Applying the controls:** Enable the relevant controls and monitoring, review their output, assign an owner to respond, and retain evidence. GuardDuty, Inspector, Security Hub, and Shield help with different risks ([Task 2.4](#task-2-4)); none makes the workload independently compliant.

## 2.3 — Identify AWS access management capabilities

**Authentication** proves who or what is signing in. **Authorization** determines what that identity may do. [AWS Identity and Access Management (IAM)](https://docs.aws.amazon.com/IAM/latest/UserGuide/introduction.html) manages access to AWS resources. **Least privilege** means granting only the actions and resources needed and adding conditions where appropriate. For example, grant a program permission to read one bucket prefix, not administrator access across the account. Review and remove access no longer needed.

| IAM building block | What it is | When to select it |
|---|---|---|
| User | A named identity in an AWS account that can have long-term credentials. | Recognize this for an existing account-specific identity or exceptional long-term credential need; prefer workforce federation or workload roles for new use cases. |
| Group | A collection of IAM users for assigning common permissions. | Attach a policy once for a group of existing IAM users. A group does not sign in or contain roles. |
| Role | An identity trusted principals or services can assume for a temporary session. | Give an EC2 application access to a bucket without storing permanent keys, or let an approved principal in another account assume a role. Trust defines who may assume it; permissions define what the session can do. |
| Policy | A document that defines permissions; it is not an identity. | Use an AWS managed policy (maintained by AWS) if suitable, or write a customer managed policy when you need reusable, tailored permissions. An inline policy is tied directly to one identity. An explicit deny overrides an allow. Managed does not automatically mean least privilege. |

[AWS IAM Identity Center](https://docs.aws.amazon.com/singlesignon/latest/userguide/what-is.html) (formerly AWS Single Sign-On) centralizes **workforce** access to AWS accounts and applications. Users can come from its directory or a connected identity source. Assign groups permission sets for the accounts they need. **Federation** lets a user authenticate with a trusted identity provider and receive temporary access instead of needing a separate long-term IAM user in each account. A **cross-account IAM role** lets a trusted principal already authenticated elsewhere obtain temporary permissions in the target account; it is not MFA. [Amazon Cognito](https://docs.aws.amazon.com/cognito/latest/developerguide/what-is-amazon-cognito.html) is for application users, such as customers signing in to a mobile app, not employee AWS console access. [AWS Directory Service](https://aws.amazon.com/directoryservice/) provides managed Microsoft Active Directory or connects AWS workloads to an existing directory, depending on the option. Think domain integration for corporate applications, not customer login.

**Credentials and safe storage:** An IAM user password policy defines requirements for IAM user console passwords; it is not a permission policy or the password policy of your external identity provider. MFA adds a separate sign-in factor; it does not authorize actions. Long-term programmatic access keys consist of an access key ID and a secret access key; temporary credentials add a session token and expire. Prefer roles and temporary credentials. Do not embed credentials in source, logs, or images; remove unused keys and replace exposed ones. [AWS Secrets Manager](https://docs.aws.amazon.com/secretsmanager/latest/userguide/intro.html) stores and retrieves secrets like database passwords and supports rotation for supported/configured uses. [AWS Systems Manager](https://docs.aws.amazon.com/systems-manager/latest/userguide/what-is-systems-manager.html) includes Parameter Store for settings and encrypted `SecureString` values; choose Secrets Manager when managed secret rotation is the goal. Both require appropriately scoped access. KMS manages keys and cryptographic operations, not the password rotation workflow.

**Root user:** Root starts with complete account access. Protect the root email and recovery channels, use a strong unique password and MFA, avoid creating root access keys (remove any unnecessary existing keys), and use delegated administrative access for daily work. Creating a bucket or launching an EC2 instance does not require root. [AWS's root-user task list](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_root-user.html#root-user-tasks) distinguishes these cases:

- For a **standalone account**, changing the root email/password or closing the account requires root; account name and ordinary contact information do not. Activating IAM access to the Billing and Cost Management console is a documented root-level task; routine billing access can be delegated after setup.
- In **AWS Organizations**, authorized administrators in the management account or delegated administrator accounts can centrally close member accounts and, with all features enabled, update member account root email addresses. With centralized root access enabled, long-term member root credentials can be removed and certain privileged tasks run centrally with scoped access. Do not apply the standalone rule to every member account.

## 2.4 — Identify components and resources for security

Use the service whose **primary job** meets the requirement. Detection creates findings; prevention blocks or reduces unwanted traffic; aggregation helps prioritize. Customers still decide how to investigate and remediate.

| Service | Primary job and scenario clue | Boundary or close alternative |
|---|---|---|
| [Amazon GuardDuty](https://docs.aws.amazon.com/guardduty/latest/ug/what-is-guardduty.html) | Detects threats from signals such as account activity, network/DNS activity, and supported workload signals; flags unusual behavior such as suspected use of compromised credentials. | Not the tool for listing missing software patches. Findings need triage. |
| [Amazon Inspector](https://docs.aws.amazon.com/inspector/latest/user/what-is-inspector.html) | Continuously evaluates supported workloads, such as EC2, ECR images, and Lambda, for applicable software vulnerabilities and exposure. | Use for vulnerable packages or supported exposure checks, not the primary detector of suspicious account activity. |
| [Amazon Macie](https://docs.aws.amazon.com/macie/latest/user/what-is-macie.html) | Discovers sensitive data in Amazon S3 and identifies S3 data security risks. | Choose for personal data in S3 objects, not for scanning arbitrary database records for vulnerabilities. |
| [AWS Security Hub](https://docs.aws.amazon.com/securityhub/latest/userguide/what-are-securityhub-services.html) | Correlates security findings and helps prioritize and respond to exposures. AWS Security Hub CSPM is the complementary posture-management service that assesses resource configurations against security controls and standards and consolidates findings. | Use the central view to triage; underlying services still do their own detection. Posture checks are not proof of regulatory compliance. |
| [Amazon Detective](https://docs.aws.amazon.com/detective/latest/userguide/what-is-detective.html) | Helps investigate a security finding by correlating related activity and showing context. | Use to investigate what happened around an alert, for example which resources were involved, not to replace the detection service. |
| [AWS WAF](https://docs.aws.amazon.com/waf/latest/developerguide/what-is-aws-waf.html) | Filters HTTP(S) requests to supported endpoints by web rules; for example, block a web request matching a malicious pattern. | Application-layer rules, not a VPC firewall or the same as broad DDoS protection. |
| [AWS Shield](https://aws.amazon.com/shield/) | Protects against distributed denial of service (DDoS). Shield Standard is provided automatically with no additional charge; paid Shield Advanced adds enhanced protections and features for eligible resources. | Think traffic flood, not a web request rule for a specific pattern. |
| [AWS Firewall Manager](https://docs.aws.amazon.com/waf/latest/developerguide/fms-chapter.html) | Centrally applies supported firewall and security policies across accounts and resources in an organization. | Use when many accounts must follow the same policy, not as the WAF rule engine itself. |
| [AWS Resource Access Manager (AWS RAM)](https://docs.aws.amazon.com/ram/latest/userguide/what-is.html) | Shares supported AWS resources across accounts or organizational boundaries where supported; for example, share subnets with accounts in the same organization. | Shares a resource rather than copying it or sending credentials; applicable permissions and sharing rules still govern use. |
| [AWS Trusted Advisor](https://docs.aws.amazon.com/awssupport/latest/user/trusted-advisor.html) | Highlights opportunities through best-practice checks, including security recommendations such as risky access configurations where covered. | Check availability varies by support plan; it is not a threat detector or a compliance certificate. See [Task 4.3](04-domain-4-billing-pricing-support.md#task-4-3). |

For example, an alert on unusual credential use points to GuardDuty; an affected application image with an outdated package points to Inspector; evidence of sensitive records in S3 points to Macie. Use Detective for investigation and the Security Hub experience for centralized prioritization. Enable and budget for the features and coverage you actually need; scans, logging, and paid protection can have separate costs.

**Other security resources:** Use the [AWS Security Center](https://aws.amazon.com/security/) for centralized security resources, [AWS Security Blog](https://aws.amazon.com/blogs/security/) for guidance and service examples, [AWS Knowledge Center](https://repost.aws/knowledge-center) for AWS-authored answers to common issues, and the [AWS Security Bulletins](https://aws.amazon.com/security/security-bulletins/) for advisories. Use [AWS Support Center](https://console.aws.amazon.com/support/home) for account or technical support according to your plan. [AWS Marketplace](https://aws.amazon.com/marketplace/) offers third-party products such as firewall appliances and security monitoring software; evaluate the vendor, contract, data handling, and pricing rather than assuming AWS operates the product or includes it at no extra cost.
